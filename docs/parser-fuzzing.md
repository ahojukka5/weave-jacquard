# Bounded parser corpus

`tests/fuzz/targets.py` exposes offline byte targets through `replay(target,
payload, directory)`. Unexpected exceptions escape; the harness catches only
named domain exceptions. Each case is replayed twice and must produce the same
acceptance/error category. Accepted source, snapshots and node maps check their
round-trip or span identity. The committed JSON corpus includes minimized
collection-valued discriminators, surrogate text, duplicate keys and malformed
compression; deterministic recipes add excessive nesting and integer precision.
No compiler, model, network service or shell program is invoked.

Run normal corpus qualification with:

```sh
python -m pytest -q tests/test_parser_fuzz_corpus.py
```

The ordinary pytest discovery includes this file. Exact production byte-limit,
limit-plus-one, compressed expansion, path/hash/count/subject mismatches and
publication tests remain in the existing bounded and semantic test families;
the byte mutator complements those contextual assertions.

## Target inventory and boundaries

| Format/boundary | Target or explicit rationale |
| --- | --- |
| Source parser and structural tree validation | `sexpr`; UTF-8 transport rejection, rendering/reparse, duplicate IDs, depth and integer boundaries. `snapshot` and `node_map` also mutate structured trees. |
| Snapshot compression, canonical JSON and hashes | `snapshot`; raw/zlib prefixes, UTF-8, truncation, duplicate keys, tree validation and exact canonical/hash round-trip. `test_snapshot_codec.py` covers exact limits, expansion bombs and revision/module/root hash mismatches. Canonical JSON accepts already parsed JSON values; arbitrary Python objects are outside its transport contract. |
| Compiler build manifest and diagnostics | `compiler_manifest`, `compiler_diagnostics`; bounded strict JSON and collection-valued status/span discriminators. Source paths/maps passed to diagnostics are generated by Jacquard. |
| Compiler capabilities/grammar handshake | `capabilities`, using the compiler package's existing validator without launching a binary. A complete maintained capability fixture seeds the corpus. Compiler implementation stages and WIR interpretation are outside Jacquard. |
| Node maps | `node_map` validates mutated trees, produces a map, and independently checks its containing root span. `source_map.smallest_node_for_span` consumes Jacquard-generated maps, not an independent ingress format. Retained map checksum/subject binding needs its artifact context: existing `test_compiler_bridge_integrity.py`, candidate-build and source-map tests supply it. |
| Retained build manifests and referenced artifacts | `build` runs the retained verifier. Existing `test_bounded_build_manifest.py` and compiler-integrity tests supply valid artifact layouts, hashes and exact limits. |
| Candidate build, candidate qualification, backup, test run, test batch metadata | `candidate_build`, `candidate_qualification`, `backup`, `test_run`, `test_batch` run their production bounded readers. These are parsing targets, not substitutes for semantic verification. Existing bounded-manifest, `test_database_backup_semantic_contract.py`, merge-candidate and test-evidence suites check cross-field and artifact relationships in live fixture contexts. |
| Common retained UTF-8/JSON file boundary | `retained_json`; strict duplicate-key handling, depth/number failures, leaf symlinks, regular-file checks and bounded reads. The harness owns the parent directory. Parent-root confinement is tested by the artifact owners' integration tests. |
| Retained public MCP/tool/application schemas | `compatibility` runs the strict semantic manifest comparator; its existing schema-classification suite tests enum/default/required-field changes. Actual MCP message decoding and JSON Schema validation belong to the pinned MCP/Pydantic dependencies and real-MCP contract tests. They are not replaced with a second decoder here. |
| Structural operation batches and database-backed verification | Existing transaction, revision and semantic integration tests own side effects, graph subjects and rollback. The complementary revision state machine in PR #289 exercises operation sequences. A byte-only target cannot validate a transaction without its database state. |
| Artifact retention/quarantine/restore manifests | Existing contract and lifecycle mutation tests retain the inventory, intent, filesystem and database context. They are intentionally outside this first stateless/reader corpus; no claim of complete semantic fuzz coverage is made. |
| Qualification traces/JUnit | Produced and consumed by `scripts/qualification.py`, outside the running server. `test_qualification_contract.py` exercises its bounded collector, counts, symlinks and trace contract. This tool's XML/JSON input is not routed through a compiler-manifest decoder. |

This PR supplies a useful bounded first corpus and fixes its discovered failures.
Issue #129 should remain open for contextual semantic fuzz targets for retained
families, structural operation batches, quarantine/restore, and real transport
qualification. Existing contextual tests are evidence of specific invariants;
they are not evidence that every possible malformed input has been fuzzed.

## Maintainer decision requested: finish as four scoped work packages

This is a proposed split, not an approved reduction of #129. Keep this PR draft
and keep #129 open until the maintainer either approves child scopes or directs
completion of the entire original scope here. No child issues are created by
this proposal. The original acceptance criteria remain in force.

| Package | Concrete work and completion evidence | Dependency |
| --- | --- | --- |
| Reader/parser corpus (this PR) | Retain the fourteen existing targets, strict bounded readers, malformed seeds, numeric/UTF-8 regressions and replay receipts. This alone does not close #129. | Rebased on merged #289. |
| Database-bound semantic evidence | Add fixture factories for committed builds, candidate builds, database backups, test runs, test batches and candidate qualifications. Invoke their production `get`/verification paths, not `_read_json` alone. Mutate project/revision/preview/definition/build identities, hashes, counts, subject links and referenced artifacts one field at a time. Independently hash bytes, reconstruct revision subjects, require a stable domain error, and prove database/artifact state is unchanged after rejection. | Existing public compiler, backup, test and merge services; no new persistence model. |
| Structural batches and artifact lifecycle | Extend the merged revision state machine with bounded malformed operation lists, alias/ID/concurrency/type/depth mutations and complete SQL rollback oracles. Add fresh quarantine/restore fixtures binding reconciliation, policy, plan, journal, capsule and payload. Mutate stale IDs, timestamps, paths, counts, hashes, interrupted stages and symlink targets; prove rejected actions neither overwrite live payloads nor follow external links. Exercise real production service methods in disposable roots. | Database-bound factories above plus existing retention/quarantine public APIs. |
| Transport/native qualification and inventory closure | Replay bounded malformed requests through actual stdio MCP and operator JSON/CLI boundaries; verify error envelopes, server-path redaction and unchanged state. Replay equivalent valid cases to establish semantic parity with in-process targets. Qualify native compiler-backed cases on an immutable supported compiler and Linux strict isolation; refusal stays a refusal when isolation is missing. Extend run receipts with context-fixture version/subject hashes and document every remaining reachable verifier or justified exclusion. | Semantic/lifecycle corpora and supported compiler/isolation resources. |

The remaining packages require different authoritative fixture graphs and
side-effect oracles. For example, `TestRunService.get` verifies output artifact
and observation hashes, candidate qualification `get` reconstructs a preview-
bound evidence graph, and quarantine/restore binds a live reconciliation plus
resumable filesystem journals. Sending the same JSON bytes to their readers
cannot exercise those contracts. Existing integration tests cover selected
invariants but do not constitute the requested systematic mutation corpus.

Each package must retain minimized failures, run deterministic seeds in normal
pytest discovery, cover valid and boundary-size fixtures, preserve existing
resource limits and isolation, and record extended-run seed, target, duration
and corpus hashes. The umbrella closes only after all original #129 criteria
have evidence. Approving the split would authorize separately scoped PRs; it
would not authorize weakening any criterion. This PR can become ready only
after the owner approves its revised linked scope and that scope has complete
acceptance evidence.

## Longer offline mutation runs

Install the development extra, then select one target, an explicit seed and a
cache destination outside the checkout:

```sh
python scripts/fuzz_parsers.py --target snapshot --seed 129 --seconds 600 \
  --output "$HOME/.cache/oodi/weave-jacquard/fuzz/snapshot-129"
```

The runner bounds individual cases to 16 KiB and elapsed time to at most one
hour. It stores `run.json` with target, seed, requested/elapsed duration, case
count, corpus SHA-256 and a streaming digest of the actual input sequence.
Memory used for accounting is constant. A failing case stops execution and is
retained as `failure.bin` with its hash; minimize it and add it to the committed
corpus before considering that regression fixed. Target functions can also be
called directly by an external coverage-guided byte fuzzer. No nightly or CI
configuration is changed.
